Discovery call playbook (60 min)

  1. Open (5 min): Attendees, decision authority, success criteria for this engagement.
  2. Problem & outcomes (15 min): Pain, users, 90-day vs 12-month success, what exists today.
  3. Workflows (15 min): Personas, journeys, volume, integrations (auth, payments, CRM).
  4. Constraints & non-goals (10 min): Budget, timeline, compliance; explicit out-of-scope for v1.
  5. Feasibility sketch (10 min): Components, risks, MVP → v1 phasing.
  6. Close (5 min): Live summary, open questions with owners; deliver written doc in 48–72 hrs.

Scenario: AI chatbot for Shopify retail client

Brief: 50k monthly visitors, reduce support tickets, ~$40k / 8 weeks.

  • Clarify: FAQ deflection vs order support vs lead gen; target deflection rate.
  • Data: Shopify catalog API, KB articles, ticket history; PII/retention policy.
  • Architecture: Storefront widget → API → RAG (embeddings + vector store) → LLM with guardrails → human handoff.
  • MVP scope: Top 20 FAQs + product lookup + email escalation; defer order changes & mobile app.
  • Deliverables: Discovery doc, one-page architecture, phased SOW, acceptance criteria.

Scenario: Scope creep mid-project

  • Document verbal asks in writing; map impact (inventory sync + mobile = change order).
  • Options: defer to Phase 2, swap priorities, or extend budget/timeline.
  • Facilitate CTO + client call with updated diagram; maintain change log.

Explain tradeoffs (non-technical audience)

PostgreSQL vs MongoDB for SaaS: Start with access patterns — relational billing/users → Postgres default; flexible nested docs → Mongo tradeoffs on reporting. Translate jargon ("ACID" → transactions won't half-save).
